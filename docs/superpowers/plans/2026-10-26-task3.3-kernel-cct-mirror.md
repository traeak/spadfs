# Task 3.3 — Kernel Keeps the cct Mirror Current

**Status: IMPLEMENTED 2026-10-30.** The draft below is kept as written; this
section records what was built and where it departs from the draft.

## As built

| Draft | Built | Why |
|---|---|---|
| Stamp at `CCT_CRC_PER_UNIT * 4` | `CCT_BACKUP_STAMP_OFF` = **16** in unit 4 | 127 × 4 = 508 is the unit's **trailer**. The free slack starts after unit 4's 4 used slots. `_Static_assert`s in `struct.h` pin both bounds. |
| `{magic, cc, txc, commit_seq}` | `{magic, cc, txc, reserved}` | Open question 1: `commit_sequence` is RAM-only, so it can't be compared after a crash. Dropped. |
| Mirror each commit's sectors | Full copy when the volume goes read-write (`spadfs_cct_backup_start`, before `spadfs_increase_cc(+1)`), then the touched block and the stamp unit on every commit | Incremental updates are only correct if the mirror started equal. A full copy at mount makes the stamp's promise true from the first commit. |
| Data → flush → CRC (CRC unflushed) | Primary data + CRC → **flush** → mirror data + CRC/stamp → **flush** | The old order let a crash *after* `fsync` returned leave a stale CRC; fsck would then fall back to the backup and lose an acknowledged commit. Cost: **one extra flush per commit**, plus one mirror block and its stamp unit. |
| Mirror failure logged | Mirror failure **clears the stamp** and stops mirroring for the mount | See the invariant below. |
| — | Never copy a primary that failed its CRCs at mount; clear the stamp instead | Copying it would overwrite the only good copy. |
| fsck: refuse when `stamp.cc < tx.cc` | Unattended restore (`-y`) only when `stamp.cc` ∈ {`tx.cc - 1`, `tx.cc`} **and** `stamp.txc` equals the mirror's own `cct[stamp.cc]`; otherwise `Q_IMPORTANT` with the age stated | `tx.cc - 1` is the kernel's working cc while mounted or after a crash. |

**The invariant** (in `struct.h`): a valid stamp promises the mirror is at most
the commit in progress behind. Any writer about to let the primary move on
without updating the mirror must clear the stamp first. Without that rule,
"same epoch" says nothing about lag. A mirror left behind early in a mount
would still carry a current-looking stamp, and fsck would restore every
acknowledged commit since without asking. Open question 2 is answered by
this rule: within-epoch lag is safe exactly because the invariant bounds it
to the unacknowledged commit.

Also fixed along the way:

- **fsck now compares the copies.** When the primary is good it checks the
  mirror against it and refreshes an out-of-date one. Verification alone never
  proved currency.
- **fsck writes CRCs and the mirror whenever it rewrites the cct** (reset,
  overwrite, reallocation). Before, `--reset-crash-counts` left the CRCs stale.
- **The backup is created once.** The create branch didn't record its result,
  and `repair_cct_backup()` ran twice, so a second backup was allocated and the
  first leaked.
- **A restore claims the cct's blocks back.** They had been freed when the
  damaged table was rejected, so `fix_apages()` would mark the cct region free.
  This dated from 3.2.
- **`validate_super()` checks the CRC and backup locations** in all three
  readers: 0 means absent; anything else must be aligned and in range.

**Not done: Task 3.4's measurement.** `tests/mirror_cost.sh` measured the full
256 KiB copy per commit (3A, ~58×). As built the per-commit cost is one block
plus one stamp unit and one flush, but that hasn't been measured on this
device.

Tests: `tests/cct_recovery.sh` (unprivileged, 49 checks) and
`tests/cct_mirror_mount.sh` (root: current / crash-snapshot restore /
damaged-primary, at 512 and 4096 blocks).

## Why this task exists

Tasks 3.1 and 3.2 built a mirror that fsck can verify and restore from. But
nothing keeps it current. Right now the mirror is written **once, by
`mkspadfs`**, and never again.

Task 3.2 turned that into a *proved* hazard rather than a suspected one.
`case_stale_backup_verifies` primes a volume and shows the mkfs mirror still
verifies as fully good while differing from the primary. Verification proves a
copy is internally consistent. It never proves the copy is current.

Restoring that stale mirror zeroes the crash-count epoch, and because
`CC_VALID(cc, txc)` is `(s32)(cct[cc] - txc) >= 0` (`spadfs.h:550`), every
structure with `txc > 0` reads INVALID — which promotes the older alternate
version. Files created since vanish, deleted files return, renames unwind. The
volume mounts and lies.

That is why 3.2 gated the restore behind `Q_IMPORTANT`. **3.3 is what makes it
safe to ungate.**

## The current commit path

`spadfs_commit_unlocked` (`super.c:729`), annotated:

```
1. sync_blockdev                          # data
2. sector = fs->cc / 128, aligned down    # which cct sector holds fs->cc
3. write cct sector(s)                    # PRIMARY DATA   (value V)
4. spadfs_issue_flush
5. fs->cct_crc[sc] = crc32c(fs->cct)     # from the SAME RAM snapshot
6. spadfs_write_cct_crc(sector, last)     # PRIMARY CRC
7. spadfs_start_new_tx(fs)               # THEN increments fs->cct[fs->cc] -> V+1
```

Two properties that the mirror must inherit, both already load-bearing:

**The CRC is computed from the same snapshot the `memcpy` used.** Step 5 reads
`fs->cct` before step 7 mutates it. A CRC taken after the increment would
describe bytes that are not the bytes on disk. The comment at `super.c:796`
states this explicitly and it is the reason 2.3 works.

**Ordering is data-then-CRC.** A crash between them leaves the CRC describing
the previous data. fsck reports a mismatch. That is the fail-safe direction —
it over-reports rather than blessing a torn cct.

---

## What 3.3 adds

After step 6, mirror the same sectors and stamp the result:

```
6. spadfs_write_cct_crc(...)              # primary CRC (unchanged)
6a. write backup cct sector(s)           # MIRROR DATA  (same V)
6b. write backup CRC units + STAMP       # MIRROR CRC, stamped
7. spadfs_start_new_tx(fs)              # unchanged
```

The mirror is written from the **same RAM snapshot** used for the primary's
CRC, so primary and mirror describe identical bytes.

## The epoch stamp — nearly free

3.2 established that the mirror needs a stamp so fsck can reason about
currency instead of guessing. The obvious worry was that adding one costs
another region. It does not.

The backup's CRC region has **492 bytes of slack that is already covered by the
unit seal**:

```
CCT_SECTORS      = 512
CCT_CRC_PER_UNIT = 127
CCT_CRC_UNITS    = 5

units 0..3 cover sectors   0..507
unit  4    covers sectors 508..511   -> 4 slots used, 123 free
123 free slots x 4 bytes  = 492 bytes, inside the sealed 508-byte cover
```

A stamp needs 16:

```c
/*
 * Packed into the unused tail of the backup's last CRC unit. That space is
 * already inside SPADFS_META_COVER and already sealed by spadfs_meta_seal(),
 * so the stamp inherits the same integrity protection as the CRCs themselves
 * and costs no additional region, sector, or write.
 */
#define CCT_BACKUP_STAMP_OFF   (CCT_CRC_PER_UNIT * 4)   /* right after the CRCs */
struct cct_backup_stamp {
	__u32 magic;		/* identifies a stamp as present */
	__u32 cc;		/* fs->cc the mirror describes */
	__u32 txc;		/* the value actually written to disk (pre-increment) */
	__u32 commit_seq;	/* fs->commit_sequence at mirror time */
};
```

`_Static_assert(CCT_BACKUP_STAMP_OFF + sizeof(struct cct_backup_stamp) <=
SPADFS_META_COVER, "stamp must fit inside the sealed CRC slack");`

**Design note:** `txc` records the value *written*, not the post-increment RAM
value. Mirroring the primary's own convention keeps the two regions directly
comparable.

## Ordering and crash semantics

The mirror goes **last**, after the primary is fully durable. That is deliberate:
the primary is the authoritative copy, and a mirror failure must never be able
to damage it or block the commit.

| Crash after | primary | mirror | stamp | fsck sees | outcome |
|---|---|---|---|---|---|
| step 3 | stale | stale | old | primary CRC mismatch, mirror valid but old | restore offered, **stamp shows staleness** |
| step 6 | current | stale | old | primary good, mirror valid but old | recreate mirror |
| step 6a | current | data current, CRC old | old | mirror CRC mismatch | recreate mirror |
| step 6b | current | current | current | both good, stamps agree | nothing |

The stamp is what turns row 1 from "restore and possibly revert data" into
"restore is N epochs behind — here is N, you decide".

**Failure policy:** a mirror write error should be logged and should mark the
mirror untrustworthy, but **must not fail the commit**. Losing the backup degrades
availability of a recovery option; failing the commit loses the filesystem.
This is the opposite of the primary's error handling and needs to be explicit in
the code, not assumed.

## Write cost

This is the thing that decides whether 3.3 ships as designed.

Per commit, cct-related writes go from:

| | before | after |
|---|---|---|
| cct data | `1 << sectors_per_buffer_bits` | ×2 |
| cct CRC units | 1 (2 when straddling) | ×2 |

On a 4 KiB-block volume that is **8 sectors → 16 sectors per commit**, plus
1–2 CRC units doubled. Roughly 2× the cct write amplification.

Mitigations worth evaluating:

- **Batch the mirror.** Mirror every Nth commit rather than every one. The stamp
  then honestly reports "mirror is N commits behind", which is still vastly
  better than "mirror is from mkfs". Trades recovery recency for cost.
- **Mirror only the touched sector**, not the whole buffer. Already the case for
  the CRC; the data write is buffer-granular because of how
  `spadfs_get_new_sector` works.
- **I/O scheduler coalescing** may make the second write cheaper than it looks —
  but only measure, do not assume.

**Task 3.4 exists to measure this.** Do not land 3.3 before the rig has run.

## fsck side

3.2's `repair_cct_backup()` needs one addition: read the stamp and use it.

```
if (primary_bad && backup_usable) {
    if (stamp absent)                  -> "mirror has no epoch stamp;
                                         cannot prove currency"
    if (stamp.cc < tx.cc)              -> "mirror is N crash epochs behind"
                                         REFUSE restore by default
    if (stamp.cc == tx.cc)             -> restore is epoch-consistent;
                                         still report commit lag
}
```

Cross-epoch reversion is the catastrophic case, so **refusing to restore when
`stamp.cc < tx.cc` is the rule that makes auto-restore safe.** Within-epoch lag
is far less dangerous and can be reported rather than blocked.

Once that is in place, the `Q_IMPORTANT` gate from 3.2 can be reconsidered for
the epoch-consistent case.

## What cannot be verified without root

Everything that matters here:

- the mirror actually lands on disk during a real commit
- crash-between-steps behaviour (needs crash injection or power-cut testing)
- write cost on real I/O patterns
- that a mirror failure genuinely does not fail the commit
- that `fs->cct` is not mutated between the primary write and the mirror write
  under concurrent load

Tasks 3.1 and 3.2 were fully provable unprivileged. **3.3 is not.** It can be
written, compiled, and reviewed — but not tested.

## Open questions

1. **Is `commit_sequence` persisted anywhere?** If not, `stamp.commit_seq` can
   only be compared against another in-RAM value, which is useless after a
   crash. Check whether the txblock carries something equivalent; if not, drop
   the field rather than ship a stamp that looks informative and is not.

2. **Within-epoch lag: how much is tolerable?** If the mirror is 3 commits behind
   within the same `cc`, restoring loses 3 transaction counts. Need to reason
   about what that does to `CC_VALID` for structures written in those commits.

3. **Should the stamp live in the backup's CRC unit 4 tail, or get its own
   sealed unit?** The tail is free but couples the stamp to the CRC region's
   geometry. If `CCT_CRC_PER_UNIT` ever changes, the stamp offset moves. The
   `_Static_assert` covers that, but a dedicated unit is more obvious at the
   cost of one sector.

4. **Does the mirror need to be a full copy at all,** or could it be
   copy-on-write against the primary with only diverged sectors stored? Probably
   over-engineering for 256 KiB, but it is the cheapest possible answer to the
   write-cost problem.
